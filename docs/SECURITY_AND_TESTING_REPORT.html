B. SQL Injection Test

RaketBase communicates with PostgreSQL exclusively through the Supabase JavaScript SDK (PostgREST API) and stored PL/pgSQL RPC functions. The application does not create dynamic SQL statements with string concatenation (e.g., db.query("SELECT * FROM users WHERE email = '" + input + "'")). The PostgREST query compiler and PostgreSQL engine automatically parameterize and escape all parameters sent via the SDK or RPC.

E. XSS Test

RaketBase's front-end presentation layer is built with React (JSX). All variables interpolated into JSX text nodes (such as {job.title}, {proposal.cover_letter}, {message.content}) are automatically encoded and escaped by React, changing < to &lt;, > to &gt;, and quotes to their corresponding HTML entities. On user-controlled input, no raw dangerouslySetInnerHTML directives are utilized.

Injection Location Payload Expected Result Actual Result Status
Job Title (CreateJob.jsx) <script>alert('XSS-Title')</script> Stored as text; rendered as harmless text string Rendered safely as literal characters <script>...; no script execution PASS
Job Description <img src=x onerror="alert(document.cookie)"> Rendered as text; image onerror does not fire Text displayed literally; zero alert execution PASS
Proposal Cover Letter javascript:alert(1) Displayed safely in proposals review card Rendered as text; no link execution PASS
Chat Message (Messages.jsx) <svg/onload=alert('XSS-Chat')> Stored in Supabase messages; rendered safely Rendered as plain text bubble; no execution PASS
Freelancer Bio / Skills "><script>alert('Bio')</script> Safely encoded on profile and public cards Encoded as HTML entities; no DOM breakout PASS
Project Title in Portfolio <iframe src="javascript:alert(1)"> Rendered inside card header as text Displays <iframe>... text; no iframe created PASS
